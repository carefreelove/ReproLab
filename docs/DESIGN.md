# 设计依据与实现

## 问题背景

缺陷描述通常省略输入边界和运行前提。ReproLab 将它转为可重复执行的测试，通过真实运行反馈修正调查路径，并保留结果的版本与原始依据。

## 技术取舍

| 问题 | 选择与依据 | 实现 |
| --- | --- | --- |
| 下一步取决于实验结果 | 使用模型驱动的工具 loop | 复用 DefaultAgent.step/query，扩展 run 生命周期和 MCP 动作 |
| 不同缺陷需要不同调查方法 | Skill 渐进加载 | 元数据目录、激活正文、资源按需取回与快照 |
| 工具需要标准通信与明确输入 | MCP Client / Server | stdio、工具发现、JSON Schema 与任务绑定 |
| 缺少可执行事实依据 | 容器测试与双版本验证 | 只读源码、独立生成测试、固定版本与测试哈希 |
| 历史越长上下文越大 | 完整轨迹与工作上下文分别保存 | 原始任务、计划、假设、活动 Skill 和近期完整交互 |
| 中断可能发生在模型响应之后 | 先持久化再执行动作 | 模型响应、稳定 tool-call ID、操作缓存与实验记录 |
| 模型调用可能未返回 usage | 预留式账本 | SQLite BEGIN IMMEDIATE 预留，共享累计预算 |

## 规划、反思与上下文

Agent 使用 update_plan 保存研究任务，record_hypothesis 保存可检验的 claim、expected、status、evidence 和 next_action。实验必须关联 active 假设。反思开启时，下一次实验和提交都要求引用上次实验日志更新假设。

引用字段只接受工具生成的原始 artifact ID。说明文字进入 claim 与 next_action。MCP 验证错误保留字段与约束信息，供模型修正参数。

完整轨迹由 mini-swe-agent 序列化。模型适配器剔除本地 extra 元数据，保留原始任务、结构化状态、活动 Skill 正文和最近完整的 assistant/tool 交互组。输入消息工作预算约 40 KB，连同工具定义的输入硬上限为64 KB。较长源码与日志按 artifact ID 取回。

任务记忆保存在 SQLite。仅通过独立验收的任务生成经验卡片，记录适用版本、Skill、有效假设和工具路径。正常任务检索同仓库、同 commit、同 namespace 的经验。评测对案例与配置隔离 namespace。

## MCP 与持久化

运行时使用官方 MCP SDK 的 Client、MCPServer 和 stdio 传输。模型工具定义来自 list_tools 的 JSON Schema，工具请求元数据携带稳定操作 ID。Server 使用独立工具锁串行处理同任务写入，完成结果按操作 ID 缓存。

生成测试写入采用临时文件替换。实验先保存 running 状态再运行，回复丢失后可复用已经完成的实验。中断实验保留状态并新建执行记录。终态任务拒绝修改类工具请求，resume 显式恢复执行阶段。

state.sqlite 包含 runs、objects、events、ledger 和 experiences。事件序号由数据库生成，调用与工具记录不使用进程内计数器覆盖更新。任务运行锁防止同任务被两个 CLI 同时执行。

## 执行与验收边界

Docker 挂载固定源码到 /workspace、生成测试到 /tests，均在执行时只读。测试临时产物进入有大小限制的 /work。容器关闭网络，以非 root 用户运行，限制 CPU、内存、进程数和时间。

目标代码和 Skill 脚本仅在容器中执行。宿主模型凭据通过客户端读取，MCP 子进程环境与容器环境采用最小配置。仓库归档拒绝路径越界和链接，限制下载、展开与单文件大小。

提交测试经过 AST 检查，再对缺陷版和修复版分别执行三次。实际采集、退出状态和 failure 类型共同参与判定。失败签名仅归一化进程内存地址，以避免对象 repr 造成稳定性误判。

静态规则与双版本测试有各自的适用边界。测试对目标行为的语义覆盖需要原始问题及测试代码共同审查，公开材料保留原始运行结果与限制。

## 费用与取消

每次调用都先在共享账本预留，API 自动重试关闭，调用 usage 返回后按高峰价格结算。发送失败或 usage 缺失保留上界并停止该任务的新调用。其他任务继续受同一总预算约束。

Ctrl+C 和任务时限会结束当前执行并保存部分结果。Docker 实验有容器内时限及宿主清理，CLI 恢复延续累计运行时间与账本。独立验收保存逐次结果，恢复时复用完成的验证。

## 验证

离线回放使用固定模型动作和预设测试，验证 MCP、Skills、实验、恢复和双版本协议。真实评测使用模型选择工具并生成测试。两种记录明确标注。单次生成对照提供固定问题和有限源码片段，未拥有执行反馈，其信息访问条件随结果保存。

## 镜像与公开产物复现

实验启动前解析本地镜像的内容 ID，并使用该 ID 执行，避免标签在运行中被重新指向。独立验收缓存同时包含镜像 ID、测试哈希、版本和重复次数。pytest 日志写入限额 tmpfs，返回日志限制为 12 KB、JUnit 限制为 256 KB；超出上限保留环境异常。Skill 脚本输出也在容器中收集，最多返回 16 KB。

公开运行包可以在新安装环境中通过 replay 重新验收。该步骤验证保存的测试与固定版本，不调用模型、不声称重新生成了原 Agent 行为。
